# 状态权威归用户，agent 写权限分级，git 只读白名单

Agent 手里握着 shell（要跑 git 扫描）、数据库和 Gerrit 三样东西，权限必须显式划界，否则一次幻觉的代价是不可逆的。三条界线：

1. **用户是任务状态的唯一权威。** 目录扫描只产出 Activity Evidence，绝不自动把任务标成完成——"有提交"不等于"做完了"，而误判会让统计与周报失去可信度，一个不可信的周报等于没有周报。Evidence 只用在两处：你主动问任务状态时展示，以及 Daily Review 时把"有活动但未标完成"的任务挑出来逐个问你。
2. **写操作分级。** 常规写（建任务、改字段、标完成、打卡、改期）agent 直接执行并回执一行，因为事件流让每一步都可一键撤销；破坏性或对外不可逆的动作（删任务、Gerrit 打分/abandon/rebase）必须走 UI 二次确认，LLM 不得自主发起。
3. **git 走只读子命令白名单**（`log` / `status` / `diff` / `branch` / `rev-list` / `show` / `shortlog`），以参数数组直接 exec、不经 shell，并拒绝 `-c` 之类的配置注入。任何写子命令（`commit` / `push` / `reset` / `checkout` / `clean`）一律不可达——扫描的是你真实的工作目录，这里没有"事后补救"。

## Consequences

- 数据边界本身**不设限**：任何 Provider 可以看到包括 diff 正文在内的全部扫描内容，这是明确权衡后的决定（换取实现最简）。配置层仍保留按用途/敏感度路由 Provider 的位置，以后想收紧不必改架构。
- Nag 有终点：同一 Task 追问累计 3 次无响应后转入 Re-decision（改期/降级/放弃），做出决策则计数清零。无上限的催办必然导致你关掉提醒，那时整个系统的价值归零。
