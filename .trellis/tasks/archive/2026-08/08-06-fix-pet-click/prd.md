# 修复宠物点击交互与开发启动

## Goal

恢复桌面宠物的意图对话入口，并保证 `run.sh` 每次启动的都是刚构建的新实例。

## Requirements

- 保留现有产品语义：双击宠物打开意图对话框，单击不触发。
- `PetView` 通过显式回调上报用户交互，不依赖 `NSApplication.shared.delegate` 的运行时类型。
- 所有重建 `PetView` 的路径必须保留同一个打开对话框行为。
- `run.sh run` 和 `run.sh kill` 必须按应用的真实进程身份停止旧实例，不能用不会出现在命令行中的 bundle id 做 `pkill -f` 匹配。
- 修复不得改变 Python 后端协议、任务数据或用户配置。
- 保持宠物窗口不抢焦点；意图对话框打开后仍可输入。

## Acceptance Criteria

- [x] 从 `run.sh` 启动后，双击宠物会显示一个意图对话框。
- [x] 对话框已打开时再次双击不会创建第二个窗口，只把现有窗口前置。
- [x] 对话框文本输入可获得键盘输入，关闭后宠物仍保持可见。
- [x] 连续执行两次 `./run.sh` 后应用 PID 会变化，且只剩一个 DayByDay 前端实例和一组后端进程。
- [x] `./run.sh kill` 能停止 DayByDay 前端及其后端进程。
- [x] `./run.sh build` 通过，无新增 warning/error。
- [x] 工作树中不引入与本修复无关的变更。

## Notes

- 自动化测试 seam：`run.sh` 的 CLI 进程生命周期（从外部观察 PID 与实例数量）。
- UI seam：真实应用窗口的双击→对话框行为。项目规范明确此类桌面交互依赖本机辅助功能权限，因此用构建检查 + 本机人工验收，不新增只验证实现细节的伪单测。
