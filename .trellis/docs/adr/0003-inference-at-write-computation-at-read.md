# 推断在写入侧，判定在读取侧

从"下周把那个重构搞完"这样一句话里，Schedule 和 Weight 是算不出来的，必须靠 LLM 推断；但如果每次查询都让 LLM 现场判断，同一个任务会今天算小烟花、明天算满屏烟花，周报数字也不可复现。因此划一条线：LLM 只在**写入时**把模糊自然语言推断成结构化字段（schedule 类型、due、weight、关联 Project）并**物化落库**；此后所有判定（该催谁、断签几天、完成率、Tier 档位）都是读这些字段的纯函数。

## Consequences

- 录入可以极随意，但系统行为稳定可测：催办策略和 Tier 函数都能单元测试，不需要 mock LLM。
- LLM 输出必须带每字段的置信度：高置信直接落库并回执一行，低置信才反问一句。推断错了，事后一句话就能改（改动本身也是一条事件）。
- 没有配置 API key 时系统降级为纯确定性模式——提醒、统计、打卡、特效照常工作，只是不能自然语言录入和生成报告文字。
