# 任务历史用事件流存储，当前状态是投影

周报/月报要回答的是"这段时间我推进了什么"和"上周三这个任务处在什么状态"，而只存当前状态的表除了完成时间戳之外会丢掉全部过程信息，这类问题根本无法回答。因此所有变更（创建、状态转移、改期、打卡、复盘回答、Activity Evidence 快照）append 到不可变的 `events` 表，`tasks` / `occurrences` 只是可随时重建的投影。

## Consequences

- Period Report 的数字全部由聚合事件流确定性算出，可复现、可核对，LLM 只负责组织成文。
- "上次活动时间"这个催办判定的核心输入天然存在，不需要单独维护字段并担心它和现实不一致。
- 撤销是天然能力：写一条指向原事件的撤销事件即可，这也是允许 agent 直接执行常规写操作的前提（见 ADR-0004）。
- 代价：每次写要同时 append 事件并更新投影，投影重建逻辑必须有测试覆盖；SQLite 里多一张只增长的表，个人使用量级下体积可忽略。
